# 用户体验简化设计方案

## 概述

本文档描述了对 Homework AI 系统的用户体验简化改造方案，主要解决以下问题：

1. **老师端评分设置页面**：包含太多专业技术参数，对普通老师来说太专业
2. **管理端**：功能复杂、菜单多，使用起来不够好用

## 设计目标

- 简化操作流程，降低用户学习成本
- 重新划分功能归属，让每个角色只看到自己需要的功能
- 保持系统功能的完整性，不减少核心功能

## 第一部分：老师端评分设置页面改造

### 现状分析

当前老师端评分设置页面 (`SettingsGrading.tsx`) 包含以下内容：

- 默认评分模式展示
- 预算模式展示
- 提供者信息展示
- 模型信息展示
- 班级评分策略设置
- 作业评分策略设置
- 高级配置展示（maxTokens、temperature、topP、presencePenalty、frequencyPenalty、timeoutMs、responseFormat、stopSequences、systemPrompt）
- 策略预览表格

**问题**：这些内容对普通老师来说太专业，理解和使用成本高。

### 改造方案

#### 页面名称

保持原名称"评分设置"，只简化内容

#### 功能简化

只保留一个简单的评分模式选择：

```
┌─────────────────────────────────────────┐
│ 评分设置                                 │
├─────────────────────────────────────────┤
│ 选择评分模式：                           │
│                                         │
│ ○ 快速模式 - 适合日常作业，速度快        │
│                                         │
│ ○ 高质量模式 - 适合重要作业，反馈详细    │
│                                         │
│ [保存]                                   │
└─────────────────────────────────────────┘
```

#### 移除的内容

- 所有技术参数展示（maxTokens、temperature、topP 等）
- 高级配置区域
- 班级/作业级别的策略设置
- 策略预览表格
- 预算模式、提供者信息、模型信息展示

#### 行为说明

- 这个设置会应用到该老师的所有班级和作业
- 不需要选择班级、作业
- 不需要"重写功能"选项
- 技术参数完全隐藏，由管理员统一配置

### 技术实现

#### 前端改动

1. 重构 `apps/frontend/src/pages/teacher/SettingsGrading.tsx`
   - 移除所有技术参数展示
   - 简化为单一的模式选择
   - 更新页面布局

2. 更新导航菜单文案
   - `apps/frontend/src/layouts/TeacherLayout.tsx`
   - 保持"评分设置"名称

3. 更新国际化文案
   - `apps/frontend/src/i18n.ts`

#### 后端改动

1. 新增 API 端点
   - `GET /api/teacher/grading-preference` - 获取当前评分偏好
   - `PUT /api/teacher/grading-preference` - 更新评分偏好

2. 修改评分逻辑
   - 在 `GradingService` 中读取老师的评分偏好设置
   - 如果老师没有设置，使用系统默认配置

#### 数据模型

在 `User` 表中新增字段：

```prisma
model User {
  // ... existing fields
  gradingPreference  Json?   // 存储格式：{ "mode": "cheap" | "quality" }
}
```

#### 数据库迁移

创建新的迁移文件，添加 `gradingPreference` 字段。

## 第二部分：管理端改造

### 现状分析

当前管理端菜单结构：

```
├── 仪表板
├── 用户管理
├── 班级管理
├── 使用统计
├── 系统
│   ├── 配置
│   ├── 预算
│   ├── 数据保留
│   ├── 系统信息
│   └── 队列
├── 诊断
├── 审计日志
├── 登录历史
├── 功能开关
└── 公告管理
```

**问题**：
- 菜单项多，没有层级区分
- 所有功能平铺展示，视觉负担重
- 高级功能和常用功能混在一起

### 改造方案

#### 菜单结构重组

```
├── 仪表板
├── 用户管理
├── 班级管理
├── 公告管理
│
├── 系统设置
│   ├── 评分配置
│   ├── 预算管理
│   └── 数据保留
│
└── 高级工具（默认折叠）
    ├── 使用统计
    ├── 队列管理
    ├── 诊断工具
    ├── 审计日志
    ├── 登录历史
    ├── 功能开关
    └── 系统信息
```

#### 菜单分组说明

1. **常用功能**（默认展开）
   - 仪表板
   - 用户管理
   - 班级管理
   - 公告管理

2. **系统设置**（默认展开）
   - 评分配置
   - 预算管理
   - 数据保留

3. **高级工具**（整个分组默认折叠，点击展开后显示子菜单）
   - 使用统计
   - 队列管理
   - 诊断工具
   - 审计日志
   - 登录历史
   - 功能开关
   - 系统信息

#### 界面文案简化

| 原文案 | 新文案 |
|--------|--------|
| 系统配置（Config） | 评分配置 |
| System Budget | 预算管理 |
| System Retention | 数据保留 |
| Submission Diagnosis | 诊断工具 |
| Audit Logs | 审计日志 |
| Login History | 登录历史 |
| Feature Flags | 功能开关 |
| System Info | 系统信息 |

### 技术实现

#### 前端改动

1. 重构 `apps/frontend/src/layouts/AdminLayout.tsx`
   - 实现菜单分组
   - 实现高级工具折叠功能
   - 更新菜单结构

2. 更新国际化文案
   - `apps/frontend/src/i18n.ts`
   - 简化文案，使用更通俗易懂的语言

#### 后端改动

无需改动，只是前端展示优化。

### 阶段二：管理端改造

1. 前端布局：重构管理端菜单结构
2. 国际化：更新文案
3. 测试验证

### 阶段三：集成测试

1. 端到端测试
2. 用户验收测试
3. 性能测试

## 风险评估

### 低风险

- 前端展示优化：只影响界面，不影响核心功能
- 文案简化：只影响显示，不影响逻辑

### 中风险

- 老师端评分设置重构：需要确保评分逻辑正确读取偏好设置
- 数据库迁移：需要确保数据完整性

### 缓解措施

- 充分的单元测试和集成测试
- 分阶段发布，先发布管理端改造，再发布老师端改造
- 保留原有 API，确保向后兼容

## 成功标准

1. 老师端评分设置页面只显示模式选择，无技术参数
2. 管理端菜单结构清晰，高级工具默认折叠
3. 所有现有功能正常工作
4. 用户反馈操作更简单、更直观
